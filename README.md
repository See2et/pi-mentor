# Pi Mentor

普段の Pi チャットで、目標・制約 → 論点 → 仮説 → 批判と弁護 → 本人の判断 → 全体整合性 → まとめを進める拡張です。フェーズの移動、論点の選択、仮説の確認、暫定採用・修正・保留は、必ず本人が操作します。AI は提案・記録だけを行います。

## 読み込む

Pi 1.0.4 / Node 24 で確認しています。

```sh
npm ci
pi --extension ./index.ts
# パッケージとしての一時読み込みも可能
pi --extension .
```

Pi が提供する型・UIライブラリを peerDependencies として使います。`npm ci` は開発・検証用です。拡張は現在の Pi モデルと認証をそのまま使用し、別プロバイダへの呼び出しや認証の変更は行いません。

## 使う

- `/mentor` から開始・再開。目標・制約と論点を入力し、「現在の論点を選ぶ」で選択します。追加だけでは論点選択やフェーズ移動は起こりません。
- メインメニューには現在の段階の操作を表示します。「記録を見る…」で閲覧、「移動・その他…」で論点／単位の選択、全体・内部フェーズへの移動、目標編集や一時停止を行います。移動は名前付きの本人操作だけで、推論や次の単位を自動開始しません。「現在の位置から対話を始める」または通常のチャットで相談してください。既存の `/mentor phase`、`hypothesis`、`draft`、`response`、`judge` などのショートカットも使えます。
- 仮説は本人が作成・改訂できます。AI 下書きは、正確な内容を本人が確認するまで現在仮説にはなりません。批判はリビジョンに紐付き、弁護・質問はメニューから本人記録できます。AI にチャットを整理させた応答は「AIによる整理・未確認」と区別されます。
- 「現在の仮説を判断する」で、内容と未撤回の懸念を確認して暫定採用・修正・保留を記録します。仮説がなくても保留できます。AI の合格判定は不要です。改訂後は旧リビジョンの判断を引き継ぎません。履歴は残ります。
- ヒントは分解・観点・知識・例示・部分案から、その都度自由に選びます。どのフェーズでも利用でき、**今回の応答だけ**に適用されます。ヒントと「対話を始める」は通常の Pi 推論を開始します。
- `/mentor status` は全記録をチャットに表示します。エディタ上のウィジェットは現在の全体・内部フェーズ、論点／単位、契約版、証拠の鮮度、判断を表示します。長い契約・証拠は閲覧画面で ↑↓・PageUp/Down・Home/End を使って読めます。Enter は閲覧から戻るだけで、確定は別操作です。
- `/mentor pause` で通常チャットへ戻り、`/mentor resume` で再開します。一時停止中は Mentor の指示を注入せず、AI の記録操作も拒否します。

メニューを Esc で閉じても記録は変わりません。開いている間に記録やセッションが変わった場合は保存を拒否するので、メニューを開き直してください。

## 実装・検証

「移動・その他…」から **実装・検証** を選べます。まとめの完了は不要です。`/mentor unitNew` で機能実装か仮説実験を選び、目的・設計参照・範囲・ID付きの具体的な期待・非目標・別項目の検証計画を入力します。正確な契約を確認してから保存し、`/mentor units` で単位を選び、メニューで実装開始を明示します。AI下書きも `/mentor unit-draft` で本人が確認するまで現在契約にはなりません。

実装・検証の実行は通常の Pi ツールを使います。AIに `mentor_status` の実観測ソースを参照して `mentor_record` の `unitEvidence` を提出させ、「証拠の検討」で期待IDごとの観測、コマンド・結果・参照、実対象／代替／未検証、限界・懸念を読みます。質問・学習メモは任意で、テスト成功や理解度の試験を合格条件にはしません。本人判断で契約版・ソース・証拠を確認し、受け入れ／修正依頼／設計に戻る／保留を選び、理由・留保を残せます。証拠不足のまま判断もできます。実験の受け入れは設計や機能の採用ではありません。

ソースは **Git追跡ファイル（変更・削除を含む）と非ignoredの未追跡ファイルの内容** を読み取って識別します。自動コミットはしません。契約や内容が変われば過去の証拠・受入を現行扱いせず、履歴だけ残します。status・メニュー・判断直前・Piツール境界で再観測し、Git外、サブモジュール／特殊ファイル、ツール実行中など観測できない場合は鮮度不明とします。これは最終確認時の一致であり、原子的なスナップショットやライブ監視ではありません。ignoredファイル、リンク先の外部内容、外部サービス、依存環境の状態は保証対象外です。

## 保存と制限

記録は Pi のセッションエントリに保存し、現在の枝だけから復元します。再開・分岐・ツリー移動・再読み込みに追従します。旧schema1の設計記録は履歴を保って読み込みます。破損・未対応データでは変更を止め、`/mentor` で確認付きのリセットを選べます（過去のエントリは削除しません）。

**Pi は、実際のユーザーまたはアシスタントのチャットメッセージがあるまで、新規セッションをディスクへ保存しません。** 新規セッションでメニューだけを操作して終了すると記録は残りません。最初の通常チャット後はそれ以前の Mentor 記録も保存されます。`--no-session` では常にメモリ内のみです。

モデルの記録ツールはフェーズ・論点選択・本人判断を変更できません。ただし、対話の進め方や批判の質はモデル次第です。採点や理解度スコアはありません。通常の Pi ファイル操作ツールはそのまま使えるため、これは書き込み禁止のサンドボックスではありません。記録はセッションに平文で残るため、秘密情報は入力しないでください。

## 検証

```sh
npm run typecheck
npm test
```

権限分離、取消、改訂の鮮度、一時停止、ヒント、競合、現在の枝の復元、UI とモデル文脈の一致を自動検証しています。インタラクティブ Pi のメニュー・入力・幅変更・ウィジェットは推論なしで確認済みです。実モデルとの対話品質・批判の妥当性は未検証です。
